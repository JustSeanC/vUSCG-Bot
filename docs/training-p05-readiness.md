Production approval remains blocked by the uncoordinated native writers. Production qualification delivery and graduation also lack installed-model, inventory and live Discord evidence. ## PIREP writer inventory and consequences

| Path | Current evidence |
| --- | --- |
| P01 Discord decision endpoint | Signed POST with timestamp window, strict ID, nonce unique key, HTTPS + rate limit. Queries/locks current row, accepts or rejects pending only, invokes the native service, verifies final state. Signed status uses the primary and does not write a report. Bridge-only transaction correctness still needs a real Laravel verification. |
| Supplied native admin status route | Admin permission is required. Controller fetches with the repository and calls changeState on the loaded model, without the bridge lock. Its service permits some reversals; those must be audited separately from a pending decision. |
| Supplied ACARS/API finalization | Api/PirepController::file invokes PirepService::submit, which can call accept/reject directly based on current state and rank auto-approval settings. Audit resubmissions and any installation routes using the same service. |
| Other native administration | The supplied store/update paths use repository operations and delete can recalculate associated state. Verify input validation and route coverage in the full installed source, including frontend manual submission, add-ons, command/scheduler jobs, alternative admin screens, queues and direct SQL writers. Inventory state changes and accounting-affecting edits/deletions, not just routes named approve. |
| Bot manual filing and training | Manual filing creates a pending PIREP and may relocate through its separate explicit option. Signoffs read PIREP evidence. Neither training nor polling updates PIREP state or credits accounting. |

The supplied native acceptance updates pilot flight time/count and rank before saving the accepted state. It then updates aircraft minutes, location, landing time and fuel, sets pilot location and last report, and dispatches acceptance and award processing. A stale second writer could re-credit minutes or flight count, issue repeated events/awards, or apply out-of-order state or locations. These are source-supported failure modes. Their exact manifestation depends on the installed UserService, write order, and listeners. Native rejection after an accepted state adjusts counters; a stale pending model can miss that branch and leave counters inconsistent with the final state. No native race was purportedly demonstrated by a Node or PHP policy mock.

The minimal safe change on the available evidence is the enforced stage-only bridge gate. A future rollout of bridge decisions requires every accepting/rejecting writer to use the same primary transaction, row lock, fresh state and proven lock ordering before invoking native accounting. Finish the inventory, test writer pairings and rollback, and independently verify listener/queue behavior. No unsupported core override or exclusive-writer guarantee was applied in P05. See the [native concurrency and rollback test matrix](training-deployment-runbook.md#native-accounting-tests).

## Test execution

Run from the branch checkout on Node v24.22.3, local disposable MySQL 8.4.13 and PHP CLI 8.1.34:

~~~bash
bash scripts/test-training-release.sh
~~~

The local P05 run passed 85 Node tests with zero failures and zero skips. PHP lint and both standalone PHP policy checks passed. The script executes npm run check, runs npm test with TRAINING_TEST_MYSQL_PORT against an empty loopback-only fixture, lints every PHP integration file, and runs PirepDecisionGateTest.php and QualificationNativePlanTest.php. This suite verifies the accumulated P01–P04 behavior plus registration, hardening, migration preflight and synthetic import regression checks. GitHub Actions runs the corresponding Node, MySQL and PHP checks on branch pushes. The separate Laravel PirepReviewBridgeTest and QualificationNativeSyncFeatureTest were syntax-checked only. Their fixture, accounting, listener and real-model assertions remain blocked. The concurrency matrix and full staging pass have no recorded results.
